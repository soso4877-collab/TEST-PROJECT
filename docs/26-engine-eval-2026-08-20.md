## 2. 설계 강점 — 특기할 것

### 2-1. 절대축/국지축 분리 (`myeongni.py`)

핵심 통찰: **절기는 태양 황경이 특정 각도가 되는 절대 시각이라 관측지 경도·균시차와 무관하다. 반면 시지는 그 자리에서의 태양 시각각 문제라 진태양시가 맞다.**

- 절대축(연주·월주·대운·세운) ← 출생 UTC를 lunar-python 절기표 프레임(CST=UTC+8)으로 환산해 투입
- 국지축(일주·시주·자시 정책) ← 진태양시

그리고 이걸 **두 개의 EightChar에서 기둥을 골라 담는 방식이 아니라, Lunar 층에서 프록시(`_SplitAxisLunar`)로 합쳐 하나의 EightChar**를 만든다. 이유가 주석에 적혀 있다 — 십성·십이운성·명궁은 전부 일간 파생값이라, 연·월주만 다른 인스턴스에서 가져오면 그 인스턴스의 일간으로 십성이 계산돼 **일간과 어긋난 십성이 조용히 섞인다**. 축을 Lunar 층에서 합치면 이 사각이 구조적으로 닫힌다. 이건 사고를 미리 한 번 더 굴린 설계다.

여기에 **fail-loud**까지 걸려 있다 — 축 미분류 메서드가 호출되면 `RuntimeError`로 즉시 터진다(조용한 축 혼입 차단).

### 2-2. lunar-python CST 함정을 이미 발견·격리

내 리서치가 "중국계 라이브러리는 절기표가 UTC+8 하드코딩이라 한국에 쓰면 절입 경계가 틀어진다"고 경고한 그 함정을, 이 엔진은 이미 실측으로 잡아 `LUNAR_PYTHON_TERM_FRAME_UTC_OFFSET_HOURS = 8` 상수로 격리했다. 실측 근거(2000 입춘 KST 21:40:22, 36개 절입 불일치 창 27.7분→0분)까지 주석에 남겼고, **"이 상수를 지우면 다음 사람이 -60분 결함을 다시 만든다"**는 경고도 붙였다.

더 인상적인 건 `docs/03`의 기록이다 — **두 결함이 상쇄 중이었다**는 진단(A: 절기표 CST라 -60분, B: 진태양시 투입으로 +46분, 합계 -14분). B만 고치면 -60분으로 **악화**된다는 것까지 파악하고 A·B를 함께 고쳤다. 부분 수정이 상황을 악화시키는 케이스를 미리 짚은 것.

### 3-2. 두 메커니즘 분리

`getSolar()`는 lunar-python의 `Yun`/`DaYun`에서 **세 가지 역할을 겸직**한다. 축은 셋 다 다르다.

| 역할 | 코드 위치 | 올바른 축 | 현행(CST) 판정 |
|---|---|---|---|
| (a) 절입까지의 **거리** 끝점 | `Yun.__compute_start`의 `current` | **절대축** | ✅ 정확 (끝점 둘 다 같은 프레임) |
| (b) **시진(時辰) 버킷팅** — 거리의 이산화 | `getTimeZhiIndex(start/end)` | **국지축**(시진은 국지 시각 개념) | ❌ **지배적 오류원** |
| (c) 起運 날짜의 **달력 앵커** / `birth_year` | `getStartSolar()`, `DaYun.__init__` | **시민 KST축** | ❌ 오류 (F-1 원 진단) |

**(b)가 진범이다.** 시진 경계는 홀수시(23·01·03·…)에 있다. CST는 KST-1h이므로 **홀수시 출생만 시진 버킷을 건너뛴다**(예: KST 03:30 寅시 → CST 02:30 丑시). 짝수시는 -1h 해도 같은 시진에 남는다(04:30→03:30 둘 다 寅). 시진이 바뀌면 `hour_diff`가 바뀌고 → 起運 년/월/일 → `start_year`가 밀린다.

**(c)는 00시대 전용이다.** KST 00:30 → CST 전날 23:30이라 달력 날짜 자체가 -1일. 00시는 전체의 1/24이므로 전체 기여도가 작다.

### 3-3. 기여도 추정

- (b) 시진 버킷: 홀수시 2.00% × 전체의 약 50% ≈ **1.0%p**
- (c) 달력 앵커: 00시대 2.82% × 전체의 약 4.2% ≈ **0.12%p**
- 합계 ≈ 1.1%p — 관측된 1.42%와 정합

**→ F-1을 "달력 앵커"로만 고치면 약 87%가 그대로 남는다.**

> **[2026-08-21 수신측 주석 — 이 기여도 분해는 재현되지 않는다]**
> 위 세 비율은 **서로 다른 표본 설계**에서 얻은 값이다(전체 1.42% = 1985~1994·7일 간격 /
> 홀·짝 = **1990~1992·3일 간격** / 00시대 = 1985~1994·매일). 기간도 간격도 달라 곱하고 더할 수 없다.
> **동일** 격자(1985~1994·연도별 리셋 7일 간격)로 다시 층화하면 홀수시 **321/12,720 = 2.52%**,
> 00시대 **32/1,060 = 3.02%**, 짝수시(0시 제외) **8/11,660 = 0.069%**, 전체 **361/25,440 = 1.42%** 다.
> 00시대 32건을 (c) 수정으로 전부 제거한다고 과대 가정해도 **329/361 = 91.1%** 가 남는다.
> 즉 **"(c) 단독 수정은 불충분하다"는 정성 결론은 유지되지만, "약 87%" 와 "1.1%p 가 1.42% 와 정합"은
> 폐기해야 한다.** 인과 기여도는 한 축만 바꾸는 **반사실 프로브**로 다시 측정해야 한다.

### 3-5. ⚠ 심각도 상향 필요 — 불일치 폭이 ±1년이 아니다

`docs/16`은 "전파는 한정적"으로 평가했으나, 불일치 **폭** 분포를 보면 그렇지 않은 꼬리가 있다.

| start_year 차이 | 건수 | 비중 |
|---|---|---|
| ±1년 | 337건 | 91.8% |
| **±9 / ±10 / ±11년** | **30건** | **8.2%** |
| 0년(간지만 상이) | 2건 | 0.5% |

**±10년 이동은 대운 슬롯이 통째로 한 칸 밀린다는 뜻이다.** `current_daewoon()`은 `start_year <= ref_year`인 마지막 대운을 고르므로, 이 케이스에서는 **"현재 대운"의 간지 자체가 달라진다.** 리포트가 "지금 당신은 ○○ 대운"이라고 서술하는 구조라면 이건 문장 전체가 어긋나는 오답이고, 정확히 `docs/16`이 근원 수정했다고 기록한 "대운 모순(정미/병오 혼서)" 사고와 같은 계열의 실패 모드다.

빈도는 전체의 약 0.1%(1.42% × 8.2%)로 낮지만, **오답의 성격이 ±1년 경계 흔들림과 질적으로 다르다.** 심각도를 "한정적 전파"에서 상향하고, 회귀 핀은 ±2 허용폭이 아니라 **정확 일치(exact)** 로 거는 것을 권한다.

### 3-6. 처방 — 프록시 재배정으로는 못 고친다

`getSolar` 하나가 세 축을 겸직하므로 `_ABSOLUTE_AXIS_NAMES`에서 빼거나 넣는 것으로는 (b)와 (c)를 동시에 만족시킬 수 없다. **한 메서드를 두 축에 동시에 배정할 수 없기 때문이다.** 어느 쪽으로 옮겨도 나머지 하나가 깨진다.

권고: **起運 계산을 lunar-python에서 회수해 자체 계산으로 옮긴다.** 이미 그럴 재료를 다 갖고 있다.

```
현재:  lunar-python Yun ← getSolar(CST) 로 거리·시진·앵커를 한꺼번에 계산
권고:  ① 거리   = |절입_UTC − 출생_UTC|        ← solarterms.solar_term_time (초 단위, 이미 보유)
       ② 이산화 = 시진 버킷을 국지축(진태양시)으로 판정   ← ct.true_solar (이미 보유)
       ③ 앵커   = 시민 KST 출생일 + 起運 년/월/일         ← ct.civil_local (이미 보유)
```

이 방식의 부수 효과가 크다 — 起運 거리의 권위가 lunar-python의 CST 절기표(분 단위)에서 **Skyfield 초 단위**로 올라간다. 즉 F-1을 고치는 김에 대운 정밀도가 한 단계 상승한다. `LUNAR_PYTHON_TERM_FRAME_UTC_OFFSET_HOURS` 의존도 대운 경로에서는 사라진다.

> **[2026-08-21 수신측 주석 — 아래 축 권고는 유파 근거로 쓸 수 없다]**
> "시진은 정의상 그 자리의 태양 시각각" 이라는 명제를 뒷받침하는 **1차 자료가 저장소에 없다**
> (`docs/00-research-ledger.md` 에서 진태양시·태양시·표준시·시진·경도 검색 0건). 엔진이 일주·시주를
> 국지축에 둔 것과의 일관성은 **구현상 장점일 뿐 유파 근거가 아니다.** 따라서 `docs/03` 결정표에
> 확정 행을 넣지 않고 **미결정**으로 둔다 — 1차 문헌 검증과 운영자 결정이 선행 조건이다.

**단, ②의 유파 판단이 선행되어야 한다.** "3일=1년" 환산에서 시진을 국지축(진태양시)으로 볼지, 시민시(KST)로 볼지는 유파 문제이고 `docs/03` 결정표에 새 행으로 기록해야 할 사안이다. 내 판단으로는 **국지축이 정합적**이다 — 시진은 정의상 그 자리의 태양 시각각이고, 엔진이 이미 일주·시주를 국지축으로 두었으므로 같은 축을 쓰는 게 일관된다. 다만 이건 명리 판단이라 최종 결정은 운영자 몫이다.

마스터플랜은 Next.js(TypeScript) 스택을 권고했는데 엔진은 Python이다. **엔진을 TS로 재작성하는 건 최악의 선택**이다 — 검증 자산(골든·3원 교차·경계 케이스)이 전부 Python에 묶여 있고, Skyfield에 대응하는 TS 천문 라이브러리는 정밀도 검증을 처음부터 다시 해야 한다. 재작성은 지금까지 쌓은 정확성 우위를 버리는 일이다.

권고: **엔진은 Python 그대로 두고 분리 배치한다.**

| 방식 | 구조 | 적합성 |
|---|---|---|
| **A. 배치 사전계산** (권장) | 명식 계산 결과를 DB(`charts` 테이블)에 적재. 웹앱은 조회만 | 마스터플랜 §5의 "결정론 → 문단 뱅크 조회" 구조와 완전 정합. 런타임 Python 불필요 |

| C. TS 재작성 | — | **비권장.** 검증 자산 폐기 |

현실적으로는 **A + B 혼합**이다. 무료 훅은 임의 입력을 받으므로 B가 필요하고, 계산된 명식은 A로 캐시해 재사용한다(마스터플랜 §10 데이터 모델의 `charts` 테이블이 정확히 이 자리). Python 엔진은 컨테이너 하나로 띄우면 되고, DE440s 천체력 파일(수십 MB)은 이미지에 포함시킨다.

### A-1. `f1_probe.py` — §3-1 스위프(표본 수·불일치율) 산출

```python
# -*- coding: utf-8 -*-
"""F-1 진단: 대운 start_year 가 '앵커 프레임'(CST vs 시민KST)에 따라 얼마나 달라지는가.

sajugen 은 절대축(연·월주·대운)을 lunar-python 절기표 프레임(CST=UTC+8)으로 넘긴다.
그런데 lunar_python 의 Yun/DaYun 은 같은 getSolar() 를 세 가지 역할에 쓴다:
  (a) 절입까지의 거리 측정 끝점        → 절대축이 맞음
  (b) 시진(時辰) 버킷팅(거리 이산화)    → 국지축 성격
  (c) 起運 날짜의 달력 앵커 / birth_year → 시민(KST) 축이 맞음
(b)(c) 가 CST 프레임으로 계산되면 start_year 가 밀린다.

여기서는 동일 출생에 대해
  A) CST 프레임 (현재 sajugen 동작)  = KST - 1h
  B) 시민 KST 프레임 (앵커로서 옳은 축)
을 각각 lunar-python 에 넣어 대운 start_year 차이를 센다.
"""
from datetime import datetime, timedelta
from lunar_python import Solar, EightChar

def start_years(y, mo, d, h, mi, is_male):
    """(a) CST프레임, (b) KST프레임 각각의 대운 start_year 리스트."""
    out = []
    for shift_h in (-1, 0):          # -1 = CST 프레임(현행), 0 = 시민 KST
        t = datetime(y, mo, d, h, mi) + timedelta(hours=shift_h)
        lunar = Solar.fromYmdHms(t.year, t.month, t.day, t.hour, t.minute, 0).getLunar()
        ec = EightChar(lunar)
        yun = ec.getYun(1 if is_male else 0, 1)
        dy = [x for x in yun.getDaYun()[1:9] if x.getGanZhi()]
        out.append((yun.getStartYear(), [x.getStartYear() for x in dy]))
    return out

def sweep(years, hours, days_step, label):
    total = 0
    diff_startyear = 0      # 대운 시작 연도 배열이 하나라도 다른 케이스
    diff_qiyun = 0          # 起運 년수(대운수) 자체가 다른 케이스
    hour_bucket_diff = {}   # 시(KST) → 불일치 건수
    for yy in years:
        d = datetime(yy, 1, 1)
        while d.year == yy:
            for h in hours:
                for male in (True, False):
                    (q_cst, sy_cst), (q_kst, sy_kst) = start_years(
                        d.year, d.month, d.day, h, 30, male)
                    total += 1
                    if q_cst != q_kst:
                        diff_qiyun += 1
                    if sy_cst != sy_kst:
                        diff_startyear += 1
                        hour_bucket_diff[h] = hour_bucket_diff.get(h, 0) + 1
            d += timedelta(days=days_step)
    print(f"[{label}] 표본 {total:,}건")
    print(f"  起運 년수(대운수) 불일치 : {diff_qiyun:,}건 ({diff_qiyun/total*100:.2f}%)")
    print(f"  대운 start_year 불일치   : {diff_startyear:,}건 ({diff_startyear/total*100:.2f}%)")
    if hour_bucket_diff:
        print("  불일치 발생 시각(KST, 30분 출생):")
        for h in sorted(hour_bucket_diff):
            print(f"    {h:02d}시대 → {hour_bucket_diff[h]:,}건")
    return diff_startyear, total
```

### A-2. `f1_cases.py` — §3-4 재현 사례·§3-5 불일치 폭 분포 산출

```python
# -*- coding: utf-8 -*-
"""F-1 구체 재현 사례 + 두 메커니즘 분리 증명."""
from datetime import datetime, timedelta
from lunar_python import Solar, EightChar
from lunar_python.util import LunarUtil

def probe(y, mo, d, h, mi, is_male):
    rows = []
    for label, shift in (("CST(현행)", -1), ("KST(시민)", 0)):
        t = datetime(y, mo, d, h, mi) + timedelta(hours=shift)
        lunar = Solar.fromYmdHms(t.year, t.month, t.day, t.hour, t.minute, 0).getLunar()
        ec = EightChar(lunar)
        yun = ec.getYun(1 if is_male else 0, 1)
        dy = [x for x in yun.getDaYun()[1:5] if x.getGanZhi()]
        cur = lunar.getSolar()
        zhi_idx = 11 if cur.getHour() == 23 else LunarUtil.getTimeZhiIndex(cur.toYmdHms()[11:16])
        rows.append(dict(
            label=label, frame_dt=t.strftime("%Y-%m-%d %H:%M"),
            sijin="子丑寅卯辰巳午未申酉戌亥"[zhi_idx],
            qiyun=yun.getStartYear(),
            start_solar=yun.getStartSolar().toYmd(),
            dy=[(x.getStartYear(), x.getGanZhi()) for x in dy],
        ))
    return rows

def show(title, args):
    rows = probe(*args)
    a, b = rows
    flag = "★불일치" if a["dy"] != b["dy"] else "일치"
    print(f"\n── {title}  [{flag}]")
    print(f"   입력(시민KST): {args[0]}-{args[1]:02d}-{args[2]:02d} {args[3]:02d}:{args[4]:02d} "
          f"{'남' if args[5] else '여'}")
    for r in rows:
        print(f"   {r['label']:10s} 프레임시각={r['frame_dt']} 시진={r['sijin']} "
              f"起運={r['qiyun']}년 起運일={r['start_solar']}")
        print(f"              대운: {', '.join(f'{sy}년 {gz}' for sy, gz in r['dy'])}")

# 메커니즘 1: 홀수시 → 시진 버킷 이동 (지배적 원인)
print("=" * 78)
print("메커니즘 ① 시진(時辰) 버킷 이동 — 홀수시 출생에서 발생")
print("=" * 78)
found = 0
d = datetime(1990, 1, 1)
while d.year <= 1991 and found < 3:
    for h in (3, 5, 9, 15, 21):
        for male in (True, False):
            r = probe(d.year, d.month, d.day, h, 30, male)
            if r[0]["dy"] != r[1]["dy"]:
                show(f"사례 {found+1}", (d.year, d.month, d.day, h, 30, male))
                found += 1
                if found >= 3:
                    break
        if found >= 3:
            break
    d += timedelta(days=1)

# 메커니즘 2: 00시대 → 달력 앵커 날짜 이동 (F-1 원 진단)
print("\n" + "=" * 78)
print("메커니즘 ② 달력 앵커 날짜 이동 — 00시대 출생(CST에선 전날)에서 발생")
print("=" * 78)
found = 0
d = datetime(1990, 1, 1)
while d.year <= 1992 and found < 2:
    for male in (True, False):
        r = probe(d.year, d.month, d.day, 0, 30, male)
        if r[0]["dy"] != r[1]["dy"]:
            show(f"사례 {found+1}", (d.year, d.month, d.day, 0, 30, male))
            found += 1
            if found >= 2:
                break
    d += timedelta(days=1)

# 불일치 폭 분포
print("\n" + "=" * 78)
print("불일치 폭(연 단위) 분포 — 1985~1994, 7일 간격, 전 시각")
print("=" * 78)
from collections import Counter
c = Counter()
d = datetime(1985, 1, 1)
while d.year <= 1994:
    for h in range(0, 24):
        for male in (True, False):
            r = probe(d.year, d.month, d.day, h, 30, male)
            if r[0]["dy"] != r[1]["dy"] and r[0]["dy"] and r[1]["dy"]:
                c[r[0]["dy"][0][0] - r[1]["dy"][0][0]] += 1
    d += timedelta(days=7)
for k in sorted(c):
    print(f"   start_year 차이 {k:+d}년 : {c[k]:,}건")
```
