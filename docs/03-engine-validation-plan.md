### 1-1. 일지 형·해·파·원진 채택표 (궁합 pairwise 전용)

> 이 항목은 궁합/관계 리포트에서 두 사람의 **일지↔일지** 상호작용만 산출한다. 계산 결과는 관계의 경향과 구조를 설명하는 참고 슬롯이며, 사건·성패를 단정하지 않는다.

| 관계 | 채택 지지쌍 | 구현 필드 | 해석 범위 |
|---|---|---|---|
| 육해(六害) | 子未 · 丑午 · 寅巳 · 卯辰 · 申亥 · 酉戌 | `PartnerFacts.ilji_hai == "해"` | 생활 흐름이 엇갈리기 쉬운 결 |
| 육파(六破) | 子酉 · 卯午 · 巳申 · 寅亥 · 丑辰 · 戌未 | `PartnerFacts.ilji_po == "파"` | 이미 묶인 매듭이 흔들릴 수 있는 결 |
| 원진(元嗔) | 子未 · 丑午 · 寅酉 · 卯申 · 辰亥 · 巳戌 | `PartnerFacts.ilji_wonjin == "원진"` | 이유 없이 서먹해지기 쉬운 감정 결 |
| 자형(自刑) | 辰辰 · 午午 · 酉酉 · 亥亥 | `PartnerFacts.ilji_xing == "자형"` | 비슷한 결이 스스로를 조일 수 있는 구조 |
| 상형(相刑, 子卯 한정) | 子卯 | `PartnerFacts.ilji_xing == "상형"` | 예의·속도 차이가 부딪힐 수 있는 구조 |

삼형(三刑) 완전판은 이번 범위에서 제외한다. 寅巳申·丑戌未는 세 지지가 갖춰져야 맥락이 완결되고,
pairwise 두 지지만으로는 寅申=충, 巳申=육합+파, 丑未=충, 戌未=파처럼 기존 합충파 판정과 섞인다.
따라서 `寅巳`는 전통 이론상 형·해 중복 후보이지만 이번 구현에서는 해(害)만 산출하고 형 필드는 빈 값으로 둔다.
추후 삼형 전체 구조를 별도 필드로 구현할 때 이 defer 결정을 재검토한다.

### 1-2. 생시 미상 세 기둥 계약

- 공개 모드는 `known|three_pillar` 두 값뿐이다. 기존 `unknown_time=True`는 입력 호환 단계에서 `three_pillar`로 정규화하되 새 주문의 정본으로 저장하지 않는다.
- 세 기둥 기준일은 사용자가 신고한 **시민 날짜**다. 후보 시각 때문에 연주·월주·일주가 바뀌는 계산은 허용하지 않는다.
- 12개 시지 후보에서 전체 구조화 값이 완전히 같은 사실만 승격한다. 11/12 동일, 일부 필드만 동일, 후보 순서에 의존한 결과는 모두 억제한다.
- 주문 메타에는 `three_pillar_schema_version=1`, `candidate_count=12`, 결정론 digest, stable/suppressed fact ID만 저장한다. 후보별 값·산문은 저장하거나 LLM에 전달하지 않는다.
- 연·월·일주, 일간, 월령 기반 격국, 알려진 세 기둥만으로 판정한 십성·신살, 달력 흐름을 기본 사실로 쓴다. 신강약·용신·오행 순위·대운 시작/현재처럼 시간에 따라 달라질 수 있는 값은 v1에서 범위로 표현하지 않고 생략한다.
- 알려진 시각 경로의 계산·문안·골든은 이 정책 변경으로 달라지지 않아야 한다.
- v1 지원 범위는 1인 명리와 integrated_full의 love/job/wealth/health 모듈이다. 상대 입력·gunghap은 두 사람 관계 사실의 12후보 불변 축약이 없으므로 fail-closed하며, 별도 정책·테스트 없이 자동 강등하지 않는다.

## 2. 만세력 3원 교차검증

- 구성: lunar-python(1.4.8 고정) ↔ Skyfield(de440s) ↔ KASI 캐시.
- 대조 항목: (a) 음↔양 변환+윤달, (b) 일진 간지, (c) 절입 시각(Skyfield↔KASI kst, 허용오차 2분), (d) 연간지(세차).
- KASI 월건은 음력월 간지 → 사주 월주(절기 기준)와 다를 수 있음. 월주는 절입시각+생시 자체 판정, 월건은 참고 대조만.
- 캐싱: 실시간 API 의존 금지. scripts/kasi_dump.py로 1900~2050 전수 → data/kasi_cache.sqlite. 절기 연 1회 증분.
- 고객 문안의 월운 표기는 맨몸 `n월`을 쓰지 않는다. 월운은 `간지월(절기명 - 양력 M/D~M/D)`로 쓰고, 음력 사고 보조가 필요할 때만 `음력 n월 무렵`을 병기한다. `지금/이번 달/다음 달` 같은 상대 시제는 기준일이 해당 간지월 절기 구간과 맞을 때만 붙인다.

## 4. 불일치 처리 정책 (런타임)

1. 3원 중 1원이라도 불일치 → 주문 상태 CALC_MISMATCH, 자동 진행 차단, 관리자 화면 적색 경고 + 어느 소스가 어떻게 다른지 표시.
   - 단, **두 계산엔진(lunar-python↔Skyfield)이 일치하고 KASI 절기만 어긋난 행이 기지 결함 목록
     (KNOWN_KASI_TERM_DEFECTS)에 있으면** 차단하지 않고 '기지 KASI 원본오류'로 분류·기록(kasi_defect_known).
     근거: 절기 timing 권위는 Skyfield(검증 lunar-python)이고 KASI는 3차 참조 — KASI 오타로 유료주문을
     차단함은 부당. 가드 완화가 아니라 불일치 출처(우리 계산 vs KASI 데이터)의 정확한 분류임.
   - 목록에 없는 새 KASI 절기 불일치(미지)는 여전히 실패로 surface(kasi_unknown_mismatches) → 조사 후
     실데이터 확인되면 목록 등록(테스트 test_full_cache_defect_inventory가 목록=실측 일치 회귀 고정).
   - 두 계산엔진 간 불일치는 예외 없이 차단(우리 계산 결함 신호).
2. 절입 ±2분 이내 출생 → 자동 판정 금지, 관리자 확인 플래그(분 단위 반올림 모호성).
3. 윤달 출생 → 15일 분할 자동 적용 + 리포트 고지 + 관리자 화면에 윤달 배지 표시.
4. 모든 불일치는 골든 스냅샷(tests/golden/)에 기록해 회귀 자산화.

## 5. 명리 메인 + 자미 보완 통합 규칙 (해석 계층)

- 최종 권위(총평·시기·길흉): 명리. 자미는 12궁 영역 서술·기질 묘사 공급 엔진으로 한정.
- 자미 대한은 "같은 시기를 다른 각도에서 본 참고 서사"로만 병기, 독립 시기 판정 금지.
- 상충 시: 명리 우선 고정, 자미 상충 서술 제외/강도 인하. 고객 문구는 "모순" 금지, 층위 차이로 재서술
  ("명리로 본 큰 흐름은 X. 자미 관점에서는 같은 시기에 Y의 결이 나타나는데, X가 진행되는 과정의 국면으로 읽습니다").
- 합치 시: "두 체계가 같은 방향" 교차 확인 문구 적극 활용.
- 주제 장(사랑·일·건강·시간·질문답변)은 층위 통합 서술이 기본 — 명리 근거와 궁 서술을 같은 호흡 안에서 겹쳐 읽는다.
  체계 이름을 앞세운 병렬 나열(엔진별 문단 스택, "명리는 X/자미는 Y" 정형)은 9장 명반 개관에서만 허용 (2026-07-05 P4, 운영자 승인 — v7 실격 후속).
- 예측 정확도 주장 전면 금지(양 체계 모두 — 린성쉬안 연구 근거). 자미 권위 문구는 역사적 권위(조선 김치 『심곡비결』)만.
