# /adjacent — 사각 인접 스캐너 (advisory)

**근거(방법론 A-4)**: 결함을 고치면 그 규칙의 경계값·이웃 조건에 같은 결함이 남는지 반드시
탐색한다. 실사례: "제 N 장" 정규식이 한 자리 장만 매칭(두 자리는 letter-spacing 공백으로 미매칭),
orphan(<40)·저밀도(<120)·장꼬리 면제의 교집합에 41~119자 무검사 구간이 있었다. 하나를 고치고
이웃을 안 보면 "고쳤다는데 반복"이 된다. 이 스킬은 **advisory** — 후보를 나열할 뿐, 게이트가 아니다.

## 절차
1. **diff 추출**: `git diff`(스테이지/워킹) 또는 `git diff main...HEAD` 로 이번 변경 라인을 모은다.
   인자 `$ARGUMENTS` 로 대상 파일/커밋 범위를 좁힐 수 있다.
2. **수정된 룰·상수 식별**: 변경 라인에서 임계값(숫자 상수)·정규식·스코프 조건(제외 집합·
   body/appendix 분리·strict_pair 등)·문구 리터럴을 뽑는다.
3. **인접 축 나열**(각 수정 룰마다):
   - **경계값**: 임계 ±1, 0, 최대, 빈 값, 자릿수 전환(한 자리↔두 자리).
   - **동치류**: 같은 규칙이 다른 단위/표기에서도 성립하는가(공백·letter-spacing·조사 변형).
   - **스코프 제외의 사각**: 제외 집합(부록·표지)의 경계에 무검사 구간이 생기는가.
   - **동일 문구 타 골격**: 같은 리터럴/패턴을 personal·gunghap(business/relationship)·
     integrated 골격이 공유하는가(grep 로 확인 — 한 골격만 고치면 나머지 미동기화).
   - **미배선 소비처**: 새 파라미터/플래그라면 소비처가 배선됐는가(팬텀 파라미터 — deadparam 참조).
4. **테스트 존재 여부 대조**: 각 인접 축에 대해 tests/ 를 grep 해 커버하는 테스트가 있는지 확인.

## 출력 표 (advisory)
| 수정 룰 | 인접 축 | 이웃 조건 | 테스트 존재 | 권고 |
|---|---|---|---|---|
| _ORPHAN_TAIL_MAX 14→90 | 경계값 | 89/90/91자 | test_render_verify? | 경계 3점 테스트 추가 |
| "제 N 장" 정규식 | 동치류 | 두 자리 장·공백 변형 | 없음 | 양방 테스트 |
| loanword body 스코프 | 스코프 제외 | 부록 경계 | test_skeleton_lint_matrix | OK |

- 말미: **테스트 없는 인접 축**만 모아 "다음 커밋에 동반 권고" 목록으로 요약.

## 규율
- advisory — 스스로 테스트를 강제하지 않는다(후보 제시). 실제 추가는 사람이 판단.
- 저확률·저영향 이웃에 과장된 무게를 싣지 마라(어설픈 게이트 회피). 심각도를 표기한다.
- 코드를 수정하지 않는다(읽기·조사만).
