## A. 검증 규율 7개조

1. **실측 우선.** 결함/완료 주장은 재현 프로브·측정치·테스트 출력으로만 한다. "아마/~일 것" 금지. 확인 못 한 것은 "미검증"으로 분리해 정직하게 보고한다.
   사례: 자시 정책 무효(P0-1)는 추론이 아니라 23:50 합성 입력 프로브로 확정했고, "짧은 관계 섹션 표제 쌓임" 가설은 실측(목차 넘침 꼬리)으로 기각됐다.
2. **증거 있는 완료 보고.** 완료 주장 = 실행 명령 + 출력(passed 수/exit code) + 커밋 SHA. 증거가 없으면 미완료로 간주한다. 근거: Anthropic 공식 "성공을 단언하지 말고 증거를 보여라" (https://code.claude.com/docs/en/best-practices).
3. **양방 테스트.** 게이트/가드/차단룰 수정은 (정상 케이스 통과 + 결함 케이스 차단) 양방 회귀를 같은 커밋에 동반한다. 결함 케이스는 합성 주입으로 만들고 PII 0. 한쪽만 있는 테스트는 완화/과탐을 감지하지 못한다.
   사례: 장꼬리 하한 도입 시 (41/67/89자=hit, 90/119자=면제) 표 테스트, 기하 게이트는 실 렌더에 결함 주입(test_render_verify.py) — fake doc 전용 테스트는 게이트 no-op 을 못 본다(2026-07-03 감사 B-2).
4. **사각 인접 탐색.** 결함을 고치면 그 규칙의 경계값·이웃 조건(단위/자릿수/스코프 제외/임계 ±1)에 같은 결함이 남는지 반드시 탐색한다.
   사례: "제 N 장" 정규식은 한 자리 장만 매칭했고(두 자리는 letter-spacing 공백으로 미매칭), orphan(<40)·저밀도(<120)·장꼬리 면제의 교집합에 41~119자 무검사 구간이 있었다. 하나를 고치고 이웃을 안 보면 "고쳤다는데 반복"이 된다.
5. **문서-코드 정합 검증.** 문서(절대규칙·결정표)가 보장하는 규칙은 코드 경로에서 실제 작동을 프로브로 증명한 것만 유효하다. 정책 enum/플래그를 만들면 소비처까지 배선하고, 정책 분기가 실제로 다른 출력을 내는 테스트를 둔다.
   사례: day_offset 은 계산만 되고 어디서도 소비되지 않아 자시 정책이 3주간 무효였다(P0-1). KASI 3원 교차·절입 ±2분 플래그도 문서에만 있었다(G-1·G-2). 3연속 사례 = 팬텀 파트너(QI-2026-07-04-01): 본인 생일 제외 가드 인자와 verify 의 product 인자가 둘 다 "받기만 하고 소비 안 되는" 상태로 방치돼, 존재하지 않는 상대의 궁합 서술이 개인 풀이에 주입됐다. **파라미터를 만들면 소비처 배선과 분기 테스트까지가 한 단위다.**
6. **근본원인 2층.** 표면 결함을 고칠 때 "왜 지금까지 못 잡았나"(감지 시스템의 구멍)를 함께 고친다. 사고는 docs/16 장부에 증상/영향/원인/재발방지로 기록하고 재발방지 액션을 추적한다. 근거: Google SRE 무비난 포스트모템 (https://sre.google/sre-book/postmortem-culture/).
   사례: 본문 좌우 비대칭(표면) + verify 에 기하 검증 0(시스템) + 재compose 과금 구조(비용)를 한 사고에서 3겹으로 고쳤다(QI-2026-07-02-02).
7. **오류 시 조사 우선.** 같은 명령 반복 금지. 공식 문서/이슈 트래커 1차 자료를 조사해 결론 내린다(docs/17 runbook 순서). 라이브러리 버전 변경은 골든 전수 재검증 동반(절대규칙 2 의 일반화).
   사례: lunar-python 이슈 #32 가 자시 일주 문제를, iztro-py 0.3.5 릴리스 노트가 대한 배정 버그를 각각 1차 자료로 확정해 줬다.

## B. 전문가급 설계·구현 규율 8개조

1. **불변식 중심 설계.** 코드가 지켜야 할 불변식을 먼저 문장으로 적는다(예: "@page margin = pdf.py margin = verify 기대치"). 불변식이 2곳 이상에 복제되면 파생 계산으로 단일화하고, 주석이 아니라 테스트로 고정한다.
   사례: .body max-width 인셋이 verify 기대치에 미반영돼 좌 14mm 밀림 사각이 생겼다 — 수정은 layout.py 단일 소스 상수화 + body_inset_lost 검사.
2. **fail-closed 기본값.** 불확실하면 진행이 아니라 차단한다(CALC_MISMATCH·brand 필수검증 패턴). 조용한 no-op(값이 없으면 통과) 금지 — 부재는 "skipped"로 구분 보고하거나 실패로 취급한다.
   사례: verify 가 spec 미전달 시 조용히 True 를 반환해 최종 발급 게이트 5종이 no-op 이었다(B-1). concern 부재 시 질문축 검사가 no-op 이었다(QI-2026-07-02-01).
3. **경계값·동치류 분석.** 새 규칙/게이트마다 경계(0·1·자릿수 전환·임계 ±1·빈 값·최대값)를 나열하고 각각 테스트 또는 "커버 안 함(사유)"을 명시한다. 단언은 좁게, 동작만 검증 — 구현 세부에 붙는 change-detector 테스트 금지 (https://testing.googleblog.com/2015/01/testing-on-toilet-change-detector-tests.html).
4. **테스트 피라미드.** 단위 다수·통합 소수·E2E 최소. E2E 는 킬러 경로(접수→생성→검수→승인→발급)만 (https://martinfowler.com/articles/practical-test-pyramid.html). 골든/스냅샷은 도크스트링에 "무엇을 검증하고 무엇을 검증하지 않는지"를 명시한다 — 무비판 갱신은 change-detector 로 전락한다. 골든의 이상형은 독립 오라클(속성 재도출·별도 구현 대조, test_golden_sweep 방식).
5. **성능은 측정 후 최적화.** pytest --durations·프로파일 실측 없이 최적화하지 않는다. 최적화 커밋에는 전/후 측정치를 필수로 남긴다.
   사례: 테스트 40% 를 차지하던 것은 렌더가 아니라 API 키 미격리 실호출 1건이었다 — 측정이 없었으면 엉뚱한 곳을 최적화했다.
6. **관측 가능성.** 실패는 원인 분리가 가능한 형태로 남긴다(exit code·stderr 캡처·마스킹된 digest). "조용히 삼키는 except: pass" 금지 — 최소 logging.warning. 관측 필드는 소비처(요약 화이트리스트)까지 배선을 확인한다.
   사례: 서브프로세스 cp949 크래시가 stderr 미캡처로 은닉됐고, 캡처를 추가하고도 hsummary 화이트리스트가 드롭해 관측 갭이 남았었다(E-5).
7. **의존성 규율.** 버전은 핀으로 고정하고, 업그레이드는 (변경로그 확인 -> 전수 테스트 -> 롤백 계획) 3단으로만 (https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json/ 의 lockfile 원칙을 pip 에 준용). 계산 스택 변경은 골든 전수 재검증.
   사례: fastapi<0.136 + starlette 1.0.0 조합은 관리자 UI 전면 크래시 — 핀이 없으면 재설치가 회귀를 부른다.
8. **리뷰 기준.** "완벽"이 아니라 "코드 건강의 명확한 개선"이면 승인한다. 설계는 원칙·데이터로, 스타일은 가이드로 판단하고 개인 취향으로 막지 않는다 (https://google.github.io/eng-practices/review/reviewer/standard.html). 저확률 결함에 고복잡·고오탐 게이트를 만들지 않는다("어설픈 게이트" 회피 — 별-궁 factcheck 기각 판정).
