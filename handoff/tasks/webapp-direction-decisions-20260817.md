## 2. 발견된 문제 3개

### 2-1. 출생지 미입력 → 서울 고정 (최대 15.8%)

`app.py:59`·CLI 기본값이 서울 경도. 출생지를 넣지 않으면 전원 서울로 계산된다.
측정: `tmp/_domestic_lon.json` (500건 표본)

| 출생지 | 시지 바뀜 |
|---|---|
| 부산 | **9.2%** |
| 강릉 | 8.4% |
| 울릉도 | **15.8%** |

**해외는 더 심각.** `time_correction.py:21,90` 이 `Asia/Seoul` 하드코딩이라 뉴욕은
**11시간 오차 + 날짜 넘어감** → 일주·시주 둘 다 오류. 측정: `tmp/_intl_probe.json`

→ **패킷 작성 완료**: `handoff/tasks/birthplace-timezone-wiring-20260817.md`

### 2-2. 자미 명반 음력이 중국 기준 (3.81%)

`ziwei.py:85` 가 양력을 iztro 에 넘겨 iztro 가 **중국 음력**으로 명반을 세운다.
KASI 한국 음력과 다른 날이 있다. 측정: `tmp/_probe4.json` (1950~2020 전일 25,933일)

| 구분 | 일수 | 비율 | 명반 영향 |
|---|---|---|---|
| 음력 월·윤달이 갈림 | 147 | **0.57%** | 命宮부터 **전부 이동** |
| 월 동일, 일만 갈림 | 841 | **3.24%** | 紫微만 이동 |

988일은 흩어진 낱날이 아니라 **연속 30개 구간**(30일×28, 89일×1, 59일×1) — 음력 한 달이
통째로 밀린 구간들.

**해결책 확인됨**: `iztro_py.by_lunar(lunar_date, time_index, gender, is_leap_month, ...)`
API가 존재한다. KASI 한국 음력을 넘기면 된다. **코드 5줄 수준.**

**중요**: 고객을 받기 전에 고쳐야 한다. 나중에 고치면 이미 발급한 고객 3.8%의 명반이 바뀐다.

### 2-3. 룰 출력 판박이 48.8%

서로 다른 사주 30명분을 룰만으로 생성(LLM 0회). 측정: `tmp/_repeat_rate.json`

```
1인당 평균 304문장 / 그중 48.8% 가 "30명 중 절반 이상에게 동일한 문장"
```

섹션별:

| 섹션 | 판박이 | 판정 |
|---|---|---|
| appendix_terms / colophon | 100% / 80% | 용어·판권 — 문제 아님 |
| **together / frame / flow** | **74.7 / 60.9 / 60.6%** | 손봐야 함 |
| consult / closing | 52.4 / 47.1% | 손봐야 함 |
| ziwei / nature / wonguk | 40.9 / 33.8 / 25.6% | 보통 |
| work_job / work / love | 11.4 / 14.4 / 19.1% | **좋음** |

→ **결론: 룰 100% 는 불가. LLM 을 판박이 5개 섹션에만 건다.** 전체의 약 1/3 → 990원
단가에서 감당 가능. 나머지 2/3 는 룰 그대로.
