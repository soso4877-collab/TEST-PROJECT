## 2. 결론 — 균시차(EoT) 하나가 국내 불일치 전부를 설명한다

포스텔러는 **경도차만** 쓴다. 확인 페이지가 보정량을 직접 표시한다.

| 도시 | 포스텔러 표시 | 경도차 계산 | 일치 |
|---|---|---|---|
| 서울특별시 | **−32분** (6월·2월·3월 **모두 동일**) | `(126.978−135)×4 = −32.09` | ✔ |
| 경상북도 울릉군 | **−17분** | `(130.906−135)×4 = −16.4` | ✔ |
| 뉴욕 주 뉴욕 | **+3분** (+ 서머타임 −60분) | `(−74.006+75)×4 = +3.98` | ✔ |

계절이 바뀌어도 서울이 항상 −32분이므로 **균시차 미포함이 확정**이다.
우리는 Skyfield 로 태양 시각각을 직접 구하므로 균시차가 자동 포함된다.

| 시기 | 우리 보정 | 포스텔러 | 차이 = 균시차 |
|---|---|---|---|
| 6/15 | −32.63분 | −32분 | **0.63분** |
| 3/10 (서울) | −42.41분 | −32분 | **10.41분** |
| 3/10 (울릉) | −26.70분 | −17분 | **9.70분** |
| 2/04 | −45.94분 | −32분 | **13.94분** |

### 예측 → 실측 검증 (핵심)

2월 차이 13.94분으로부터 **포스텔러 입춘 전환 = 우리(21:27) + 13.94 = 21:41** 을 예측하고
실측으로 확인했다.

```
21:27  포스텔러 己卯 丁丑  (미전환)   ← 우리는 여기서 전환
21:40  포스텔러 己卯 丁丑  (미전환)
21:41  포스텔러 庚辰 戊寅  (전환)     ← 정확히 예측대로
```

**차이 정확히 14분.** 균시차 가설이 분 단위로 검증됐다.

6월도 같은 방향: 차이 0.63분 → 자시 경계 1분(우리 23:33 / 그들 23:32), 망종 절입 1분.

### 실무 영향 — 절대규칙 7 재검토 필요

E1 이 중요하다. `09:35` 는 포스텔러 경계(09:30)에서 **5분이나 떨어져 있는데도 불일치**했다.
우리 균시차가 −10분이라 시지 경계를 반대편으로 넘겼기 때문이다.

> **즉, 불일치 구간은 "경계 ±1분"이 아니라 "경계 ±균시차(최대 약 14분)"다.**
> 하루 12번의 시지 경계마다 이 폭이 생긴다.

> **[정정] 여기서 "절대규칙 7의 ±2분을 ±15분으로 넓혀야 한다"고 적었던 것은 철회한다.**
> KASI 절기 원본과 대조한 결과, 절입 불일치(B2·C2)는 유파 차이가 아니라
> **우리 엔진의 시각축 결함**이었다. 규칙을 넓혔다면 결함을 정책으로 덮는 꼴이 됐다.
> 상세와 수정 제안은 `solar-term-axis-defect.md`.

**시지·자시(A1·E1)는 유파 차이가 맞고 우리 쪽이 정당하다.** 시지는 태양의 실제 시각각
문제라 균시차 포함이 더 정밀하다. **절입(B2·C2)은 우리 결함이다** — 절기는 절대 시각이라
경도·균시차를 적용하면 안 되는데 적용하고 있었다.

## 3. 12간지 시간표는 근사치, 실제 계산과 다르다

모달 표는 자시를 `23:30~01:30` 으로 고지하지만 **실측 전환은 23:32**(A1/A2)였다.
표는 −32분을 **−30분으로 반올림**한 안내용이고 내부 계산은 −32분을 쓴다.
→ 우리가 비슷한 안내표를 만든다면 **표와 계산이 어긋난다**는 걸 알고 만들어야 한다.

## 4. 대운 — 방향은 일치, 대운수는 체계적으로 1 차이

| | 우리 | 포스텔러 |

| D1 (2000/09/09 **남**, 경진=양년) | **9**, 순행 | **10**(을유), 순행 `丙→丁→戊` |

만 나이 vs 세는 나이 관례 차이로 **보인다**. 2건만 확인했으므로 **전수 검증 필요**.

  무조건 좋고 충이라고 해서 꼭 나쁘게 작용하지 않습니다."
  → 우리 절대규칙 11(예측 정확도 주장 금지)과 같은 방향

## 12. 미검증 항목 (단정 금지)

- **대운수 +1 차이**: 2건(D1·D2)만 확인. 관례 차이로 **보이나** 전수 미검증
- **GeoNames**: ID 3건이 일치하나 **GeoNames 원본 DB 와 직접 대조하지 않았다.** 라이선스 원문도 미확인
- **공망 산출 기준**: 화면 문구가 `일간 기준`이나 실제 계산 기준 미검증
- **부가탭**: 한 명식(庚辰 戊寅 壬辰 辛亥)에서만 수집. 다른 명식의 표시 차이 미확인
- **윤달·시진 불명**: 입력 UI 존재만 확인, 산출 대조 **미실행**
## 13. 야자시 토글 ON 실측 (2026-08-17 추가)

`야자시/조자시` 라디오를 켜고 재실행했다. 라디오 checked 상태를 DOM 으로 확인한 뒤 제출했다.
우리 값은 `yajasi-ours.json` 에 **브라우저 열기 전 동결**.

| 입력 (서울, 남) | 포스텔러 (야자시 ON) | 우리 `YAJASI_SPLIT` | 판정 |
|---|---|---|---|
| 2000/06/15 **23:33** | 庚辰 壬午 **甲辰** 丙子 | 庚辰 壬午 **甲辰** 丙子 | **일치** |
| 2000/06/16 **00:20** | 庚辰 壬午 **甲辰** 丙子 | 庚辰 壬午 **甲辰** 丙子 | **일치** |

- 야자시 OFF(기본) 23:33 → `乙巳`(익일) / ON → `甲辰`(당일). **일주만 바뀌고 시지는 子 유지.**
- 00:20 은 포스텔러 화면 표기가 `2000/06/15 23:48 (지역시 -32분)` 로 **날짜가 전날로 되돌아간다.**
- 일주 별명도 `을사(푸른 뱀)` → `갑진(푸른 용)` 으로 바뀐다.

> **결론: 우리 `ZasiPolicy` 두 값의 의미가 포스텔러의 토글과 정확히 같다.**
> `JST_2300` = 토글 OFF(기본), `YAJASI_SPLIT` = 토글 ON.
> enum 설계가 외부 서비스와 의미상 호환됨을 확인했다. 절대규칙 6 유지에 문제없다.
