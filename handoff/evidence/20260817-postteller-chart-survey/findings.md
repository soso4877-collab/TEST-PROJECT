## 1. 유파 — 포스텔러가 스스로 문서화한 것 (가장 중요)

### 1-1. 자시 정책 (`야자시/조자시` 도움말 원문)

> 사주에서 하루가 바뀌는 자시는 **저녁 11:30**에 해당합니다. 그런데 야자시는 이 자시를 둘로 나눠
> 12시에 날짜가 변경되는 현대 시간 개념을 적용하는 것입니다.
> 예를 들어 서울 기준, 저녁 11:30~00:00 사이에 태어난 경우, 시간 값은 그대로 두고 **일자를
> 전날로 변환**하여 해석하는 방식입니다.
> **일반적인 해석방법은 아니나** 포스텔러에서는 다양한 풀이방식을 제공하고자 야자시/조자시를
> 선택하실 수 있도록 하였습니다.

**해석**

| | 포스텔러 | 우리 |
|---|---|---|
| 기본값 | 23:30(서울 시민시각) = 23:00 지역시부터 자시, **일주 익일 전환** | `ZasiPolicy.JST_2300` — 동일 |
| 선택지 | 야자시 ON = 23:30~00:00 은 일자를 전날로 | `ZasiPolicy.YAJASI_SPLIT` — 동일 |
| 주류 판정 | 야자시를 **"일반적인 해석방법은 아니다"** 라고 명시 | 기본값이 JST_2300 |

→ **절대규칙 6(자시 기본 = JST_2300)의 외부 근거를 확보했다.** 경쟁 서비스가 같은 기본값을
쓰면서 반대 학설을 "일반적이지 않다"고 자사 도움말에 적어두었다.

### 1-2. 12지지 경계표 (`12간지 시간표` 모달, 원본 이미지 `postteller-12branch-table.png`)

| 간지 | 시간 | 간지 | 시간 |
|---|---|---|---|
| 자시 | 23:30(전날)~01:30 | 오시 | 11:30~13:30 |
| 축시 | 01:30~03:30 | 미시 | 13:30~15:30 |
| 인시 | 03:30~05:30 | 신시 | 15:30~17:30 |
| 묘시 | 05:30~07:30 | 유시 | 17:30~19:30 |
| 진시 | 07:30~09:30 | 술시 | 19:30~21:30 |
| 사시 | 09:30~11:30 | 해시 | 21:30~23:30 |

**전 경계가 `:30`** 이다. 서울 지역시 보정 −32분을 **시민시각 표에 미리 반영**한 형태다.
모달 안내문: "간지에 맞춰 시간을 입력하실 때는 시스템 자동 보정값을 고려해 1시간 이상 늦은
시간을 쓰시는 것을 추천드립니다."

### 1-3. 시각 보정 방식 — 균시차 미포함으로 **보임** (추가 검증 필요)

확인 페이지가 보정량을 명시한다: **"입력하신 지역 정보에 따라 −32분을 보정합니다."**

`(126.978 − 135) × 4 = −32.09` → **경도차만.** 균시차(EoT)를 넣으면 계절에 따라 ±14분
움직여야 한다. 6월 케이스에서 −32분인 것만으로는 확정할 수 없으므로(6월 EoT ≈ 0)
**2월 케이스(C1, EoT ≈ −14분)에서 −32분이 유지되는지 확인해야 확정된다.** → §4 미완

## 2. 실측 대조 — A1/A2 자시 경계 (완료)

입력: `2000/06/15 23:32`, 남, 서울특별시

| | 사주 | 일주 |
|---|---|---|
| 포스텔러 | 庚辰 壬午 **乙巳 丙子** | 익일 전환됨 |
| 우리 23:32 (A1) | 庚辰 壬午 **甲辰 乙亥** | 아직 당일 |
| 우리 23:33 (A2) | 庚辰 壬午 **乙巳 丙子** | 익일 전환됨 |

**자시 전환 시각이 1분 어긋난다.** 포스텔러는 23:32 − 32분 = 23:00 정각을 경계로 삼아
**경계 포함(>=)** 으로 넘긴다. 우리는 균시차까지 반영해 23:33 에 넘긴다.

> **판정 보류**: 어느 쪽이 "틀렸다"고 말할 수 없다. 균시차를 넣는 우리가 천문학적으로 더
> 정밀하고, 포스텔러는 재현 가능한 고정 규칙을 택했다. **유파 차이이지 오류가 아니다.**
> 다만 경계 ±1분 출생자는 두 서비스 결과가 다르므로, 고객 대응 문구가 필요하다.
> (절대규칙 7의 "절입 ±2분 관리자 확인 플래그"와 같은 성격의 문제가 자시 경계에도 있다.)

## 3. 명식 화면 정보 구조 (벤치마크)

포스텔러 결과 화면은 **전부 DOM 텍스트**다(12간지 표만 이미지). 구성 순서:

1. **머리말 3줄** — 일주 별명(`을사(푸른 뱀)`), 양력 입력, 음력 환산(`음(평달) 2000/05/14`),
   **보정 적용값**(`2000/06/15 23:00 ... (지역시 -32분)`)
   → 입력·환산·보정을 **세 줄로 나란히** 보여준다. 재현 가능성을 화면에서 증명하는 방식.
2. **본 명식 표** — 행 7개 × 열 4개
   행: 천간 / 십성 / 지지 / 십성 / 지장간 / 12운성 / 12신살
   열: 생시 / 생일 / 생월 / 생년 (**시→년 역순**)
   천간·지지마다 음양오행 병기(`병丙 +화`, `자子 -수`)
3. **사주 풀이 자세히 보기** — 탭 12종:
   `궁성 · 천간합 · 지지육합 · 지지삼합 · 지지방합 · 천간충 · 지지충 · 공망 · 형 · 파 · 해 · 원진`
4. **궁성** — 기둥마다 시기 + 인물 2겹 매핑
   생시=말년운(자녀운·결실) 아들/딸 · 생일=중년운(정체성·자아) 자신/배우자 ·
   생월=청년운(부모·사회상) 부친/모친 · 생년=초년운(조상·시대상) 조부/조모
5. **신살과 길성** — 이름 나열 후 기둥별 배치표 (A1 케이스 17종)
6. **오행과 십성 분석** — 백분율 + 3단 라벨(`적정` / `과다` / `발달`),
   토글 2개: `합에 따른 오행 변화 적용`, `조후와 궁성 보정값 적용`
7. **나의 오행** — 생(生)·극(剋) 관계도, 비겁/식상/재성/관성/인성 5분류 백분율
8. **신강/신약지수** — `득령·득지·득시·득세` 4요소 + 분포 그래프 +
   **"20.19%의 사람이 여기에 해당합니다"** (희소성 지표)
9. **용신** — `수(억부용신)`
10. **대운** — 대운수 `7(임오)`, 10주기, 각 주기에 십성 + 12운성
11. **연운** 10년 / **월운** 12개월 (동일 형식)
12. **일진 달력** — 월 단위, 일별 일진 간지 + 음력일, **절기는 시각까지**(`입추 20:41`)

### 우리가 없는 것

| 항목 | 포스텔러 | 우리 |
|---|---|---|
| 합·충·형·파·해·원진 | 12종 탭 | 공망만 |
| 신강약 백분위 | "20.19%의 사람이 여기에 해당" | 없음 |
| 궁성 (시기 + 인물 2겹) | 있음 | 없음 |
| 조후용신 | 억부 + 조후 | 억부만 |
| 오행 3단 라벨(적정/과다/발달) | 있음 | 백분율만 |
| 일진 달력 + 절기 시각 | 있음 | 없음 |
| 오행 보정 토글(합 변화 / 조후·궁성) | 사용자 선택 | 없음 |
| 일주 별명(`을사(푸른 뱀)`) | 있음 | 없음 |

## 4. 입력 UI 실측 (우리 출생지 패킷에 직결)

| 항목 | 실측 |
|---|---|
| 달력 | `양력` / `음력` / **`음력(윤달)`** 3종 (`value=S/M/L`) |
| 시진 불명 | `시간 모름` 라디오 **있음** |
| 자시 정책 | `야자시/조자시` 라디오 — **사용자가 유파를 고름** |
| 도시 검색 | **부분 문자열 불가.** "서울"=0건, "서울특별시"=1건. **Enter 제출 방식**(라이브 자동완성 아님) |
| 도시 표기 | `서울특별시, 대한민국` — `지명, 국가` |
| 미입력 안내 | "태어난 도시를 모르시는 경우 '서울특별시' 혹은 태어난 국가의 수도를 입력해주세요" |
| 보정 고지 | 확인 페이지에서 `-32분` 명시 |
| 이름 | 최대 12글자, 합성값 사용 |

→ **우리 tz 패킷 §6-2 (가) 도시 검색 결정에 직접 반영**: 포스텔러조차 부분 문자열 검색을
포기하고 정식 명칭 + Enter 제출로 갔다. 자체 표로는 불가능하다는 rev2 판단을 재확인한다.
동시에 **"수도를 입력하세요" 폴백**은 우리도 쓸 수 있는 저비용 안전장치다.
